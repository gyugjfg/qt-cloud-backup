# 云备份项目素材清单

把截图放在本目录，把视频放在 Release 素材目录；文件名保持下面的英文命名，便于 HR 和 GitHub 页面理解。截图使用样例节点、样例文件名和脱敏地址，不要出现真实用户目录、IP、账号或密码。

## 截图顺序

| 文件名 | 画面内容 | 必须展示 |
| --- | --- | --- |
| `01-upload.png` | 上传页 | 本地文件选择入口、目标节点和上传工作区 |
| `02-download.png` | 下载页 | 远程目录浏览、节点状态、文件选择和下载入口 |
| `03-task-progress.png` | 任务页 | 进行中/已完成任务、进度和暂停/开始/删除操作 |
| `04-node-management.png` | 节点管理页 | 节点名称、地址、端口、在线状态和节点操作 |

截图建议 1600x1000 或 1920x1080，PNG/JPEG 单张控制在 2 MB 左右。不要使用包含浏览器标签、桌面全屏、真实路径或个人通知的截图。

## 综合视频

建议只录制一个综合演示：`cloud-backup-linux-e2e-demo.mp4`，时长 60-90 秒。

```text
00:00-00:08  WSL 启动服务端，展示专用存储根目录和监听端口
00:08-00:18  Windows 客户端打开节点管理，连接示例节点
00:18-00:32  浏览远程目录并选择示例文件
00:32-00:52  创建上传或下载任务，展示进度、速度和任务状态
00:52-01:08  若当前环境稳定，暂停后恢复一次，展示偏移续传
01:08-01:20  WSL 终端展示 fileput/filesave 日志，客户端显示完成结果
```

只有真实复现客户端到 Linux 服务端的链路后，才能把视频标题写成 `e2e`。如果暂停/恢复没有稳定复现，就删掉该段并只保留已验证的上传或下载流程；单边画面应改成 `client-demo` 或 `server-protocol-demo`。

## 录制前检查

- 使用临时演示目录和虚构节点，例如 `demo-node`、`127.0.0.1` 或 WSL 可达示例地址；
- 不展示 SSH 密钥、密码、云账号、真实 IP、用户目录或其他项目文件；
- 录制前清空无关任务和通知，确保客户端与服务端日志时间线连续；
- 上传/下载完成后至少保存一次文件大小或 SHA-256 结果，方便面试时解释验证边界；
- 录制完成后再把文件复制到本目录或 Release 素材目录，不把视频加入普通 Git 提交历史。
